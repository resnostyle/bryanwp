## Project: Personal Link Hub (Astro Static Site)

### 1. Goal

Build a fast, minimal personal “link hub” site (similar to Linktree) that:

* Lists curated links to external sites/services
* Is fully static at build time
* Can be deployed now in Kubernetes and later migrated to Cloudflare Pages without changes to source structure

---

## 2. Tech Stack

* Framework: Astro
* Styling: Tailwind CSS (preferred) or minimal custom CSS
* Output: Static site (`dist/`)
* Hosting (initial): Kubernetes (NGINX container)
* Hosting (future): Cloudflare Pages

---

## 3. Core Requirements

### 3.1 Static-first architecture

* No SSR
* No backend runtime
* No database dependency
* Output must be pure static assets in `/dist`

---

### 3.2 Content model (important)

All links must be driven from a single structured file:

Example:

```
/src/data/links.json
```

Structure:

```json
{
  "title": "My Links",
  "description": "Short bio",
  "links": [
    {
      "label": "GitHub",
      "url": "https://github.com/username",
      "icon": "github"
    },
    {
      "label": "Blog",
      "url": "https://example.com"
    }
  ]
}
```

Rules:

* No hardcoded links in components
* All links must come from this file
* Easy to extend later (categories optional)

---

### 3.3 Pages

#### Required pages:

* `/` → main link hub
* `/404` → simple fallback page

Optional:

* `/about` (only if needed, otherwise skip)

---

### 3.4 UI requirements

Homepage layout:

* Centered layout
* One header section:

  * Name or brand
  * Optional short description
* Link list:

  * Large clickable buttons or cards
  * Full-width on mobile, constrained width on desktop
* Subtle hover states only

Design rules:

* No clutter
* No animations beyond simple hover transitions
* Mobile-first responsive design
* Fast load (no heavy libraries)

---

### 3.5 Link behavior

Each link:

* Opens in new tab (`target="_blank"`)
* Has `rel="noopener noreferrer"`
* Must be accessible (keyboard navigable)

---

### 3.6 Build output requirements

* Must generate static output in `/dist`
* Must be deployable via:

  * NGINX container (Kubernetes)
  * Cloudflare Pages later without modification

---

## 4. Deployment requirements (Kubernetes)

* Use a minimal container:

  * NGINX or equivalent static file server
* Serve `/dist` directly
* No Node runtime required in production container
* No SSR server running

Example expectation:

* Container = static file host only
* No build step inside container (build happens in CI)

---

## 5. CI/CD expectations

* Build step runs:

  * `npm install`
  * `npm run build`
* Output artifact: `/dist`
* Deploy artifact into container image or volume

---

## 6. Future-proofing requirements (Cloudflare migration path)

Site must be compatible with:

* Cloudflare Pages (static hosting)
* Optional enhancement via:

  * Cloudflare Workers for redirects/tracking

To support this:

* Avoid hardcoded redirect logic in frontend
* Prefer `/go/<name>` style internal links for future routing flexibility

Example:

```
/go/github → later becomes Worker-managed redirect
```

---

## 7. Non-goals (explicitly excluded)

* No backend API
* No user accounts
* No CMS dependency
* No database requirement
* No SSR frameworks
* No Kubernetes-native coupling in app code

---

## 8. Nice-to-have (optional)

* Dark mode toggle (local state only)
* Simple click analytics (later via Cloudflare Workers or external tool)
* SVG icons for links
* Simple grouping (e.g., “Work”, “Social”, “Projects”)

---

## 9. Acceptance criteria

* Site builds to static `/dist`
* Fully functional without any backend
* Deployable in Kubernetes with one static container
* Deployable to Cloudflare Pages without code changes
* All links configurable via single data file
* Mobile-friendly and fast load time (<1s typical)
